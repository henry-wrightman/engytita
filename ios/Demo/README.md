# iOS reference sample

Minimal SwiftUI app that drives **Engytita** on two physical iPhones:

1. Broadcast / read an 8-byte EID over GATT (see limitation below)
2. Sans-I/O Noise pairing with **manual SAS digit entry**
3. Session request/accept and STS+transport key derivation (keys not logged)

## Limitation (read this)

iOS apps **cannot** set arbitrary legacy Advertising Data. The normative
15-byte layout from `engytita-ble` is for platforms that can (e.g. Android).
This sample puts the EID on a GATT characteristic under service UUID
`0xE671` instead. Resolution still uses `Engytita.resolve`.

Nearby Interaction ranging is **untrusted** / not keyed by Engytita.

CI does **not** build this Xcode project.

## Build

From the repo root:

```bash
./scripts/generate-bindings.sh          # if FFI changed
./scripts/build-ios.sh                  # engytita-ffi → XCFramework
python3 scripts/generate-ios-xcodeproj.py
open ios/Demo/EngytitaDemo.xcodeproj
```

In Xcode:

1. Set your **Team** for signing (`org.engytita.EngytitaDemo`).
2. Select two physical devices if possible (BLE does not work usefully between
   simulator and phone for this flow).
3. Run.

## Two-phone test plan

1. Install on phone A and phone B (different entropy → different peer ids).
2. On **B**: tap **Advertise as responder**.
3. On **A**: tap **Scan as initiator**, then **Connect & pair** when B appears.
4. When both show SAS: compare verbally, type the six digits, **Confirm SAS**.
5. Expect “Keys derived ✓” on both after accept.

Wrong digits must fail pairing.
